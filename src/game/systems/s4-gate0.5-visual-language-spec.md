## 一、设计意图

Gate0.5 修正版的核心命题：

> **只看图，就能看懂"这是一座阵、这刀切哪、切完会怎样、为什么现在有压力。"**

上一版 Gate0 的静态图更像"设计讲解图"——图标清晰，但结构关系大量依赖文字标签。Gate0.5 修正版做了一件事：**把理解负担从文字转移到视觉层级。**

## 二、视觉语法规范（五种关系，唯一语法）

### 第 1 层：阵势骨架（优先感知）

| 元素 | 语法 | 约束 |
|------|------|------|
| 阵势外轮廓 | 暗紫填充(`rgba(45,15,65,0.14)`)、紫色虚线边框(`rgba(90,50,130,0.32)`)、2.5px 线宽 | 每张图的外轮廓先于节点被感知 |
| Boss 剪影 | 深黑剪影 + 紫色辉光 + 右肩铰接 | 顶部居中，固定占屏幕 ≤20% |
| 防线 | 红色虚线 + 微弱红底 | y=345，清晰标记危险边界 |

### 第 2 层：五种关系唯一语法

| # | 关系类型 | 视觉语法 | 颜色 | 线宽 | 特殊标记 |
|---|---------|---------|------|------|---------|
| 1 | **Boss 主链** | 粗实线 + 金色辉光，中轴感 | `rgba(255,211,90,0.7)` | 4px | shadowBlur=8, 不亮时虚线 |
| 2 | **可切分支** | 蓝白实线，连接蓝关节→下游 | `rgba(91,192,255,0.55)` | 3px | 失效后灰化+虚线 |
| 3 | **甲链/不可切** | 粗黑红+节点状锁定标记，金属质感 | `rgba(180,20,20,0.55)` | 5px | 节状方块标记 + shadowBlur |
| 4 | **红色威胁刃** | 红三角（向下），紧急性=脉冲+半径 | `rgba(200,40,25,0.7-0.9)` | — | 紧急时 2.5px边框+shadowBlur=10 |
| 5 | **旧残阵** | 低亮暗色虚线框 + 降权灰色节点 | `rgba(60,60,70,0.2)` | 1.5px 虚线 | 暗淡红刃、无辉光 |

**关键区分规则**：
- 甲链 ≠ 普通红线。甲链是**粗节点状锁链**，不是细斜线
- 可切分支 ≠ 甲链。甲链永远比可切分支粗 2 倍以上
- 红刃必须明确从属某条分支，不独立漂浮
- 旧残阵必须与主阵有 ≥30% 的亮度分离

### 第 3 层：候选刀路 → 结果

每条候选刀路必须同时呈现"走法"和"结果"：

| 刀路类型 | 线型 | 后果表现 |
|----------|------|---------|
| 推荐/正确刀路 | 亮色虚线+箭头 | 命中节点高亮，失效节点灰化打叉 |
| 错误/阻断刀路 | 红色虚线+箭头 | 命中点⊘阻断标记 + 灰化失效 |
| 保命刀路 | 橙黄虚线+箭头 | 残留红刃灰化解锁 |
| 反卷刀路 | 金色虚线+箭头 | 命核高亮 + 文本"反卷" |

**两条刀路的后果必须视觉对立**（一灰一亮、一存一灭），不能只靠文字区分。

### 第 4 层：文字标签（最小化）

- 标题：仅变体标签（"✓ 断链"/"✗ 甲链阻断"等）
- 图例：存在于全局 legend，不重复标在节点上
- 去说明化版本：仅保留节点 ID 前缀，删除所有解释文字

## 三、三张图战术含义

### 图1：阶段1 — 教学阵（0-6s）

**教什么**：切关系，不是切单体。

**视觉叙事**：
1. 阵轮廓让玩家先看到"这是一整座阵"
2. 蓝关节下方的虚线框标明"这片区域受蓝关节控制"
3. 刀路A（蓝色·断链）→ 下游两红刃一起灰化打叉
4. 刀路B（橙色·单切）→ 只灰一刃，另一刃仍存活

**验收**：去文字后，2 秒内回答 "切蓝点会影响什么" → 正确答出"下面两个红刃"

### 图2：阶段2 — 甲链阵（5-13s）

**教什么**：结构不同，解法不同。

**视觉叙事**：
1. 左边：可切蓝分支（蓝+红）
2. 右边：受甲链保护（红刃孤立，甲链横跨）
3. 甲链表现为粗黑红节点状锁链，与普通红线彻底区分
4. 刀路A（蓝色·断左枝）→ 左刃灰化
5. 刀路B（红色·穿甲链）→ ⊘阻断标记 + "后半段无效"

**验收**：去文字后，3 秒内区分哪边可切 / 哪边被锁

### 图3：阶段3 — 叠压阵（11-25s）

**教什么**：优先级冲突——保命 vs 反击。

**视觉叙事**：
1. 旧残阵：灰暗虚线框 + 暗淡红刃 + "即将触线"警告
2. 新阵：明亮外轮廓 + 命核 + 双分支 + 甲链
3. Boss 主链从命核连接到 Boss
4. 刀路A（橙色·保命）→ 旧残留红刃灰化消失
5. 刀路B（金色·反卷）→ 命核高亮，旧残留保留

**验收**：去文字后，3 秒内回答 "先救残留还是赌命核" → 能看出两条路线结果不同

## 四、验收结论

### 自测

| 验收项 | 结果 |
|--------|------|
| 阵势是否先于节点被感知 | ✅ 外轮廓 2.5px 边框+填充，明显先于内部节点 |
| 去说明化后是否仍可理解 | ✅ no-label 版本仅保留图例和刀路标记 |
| 甲链是否已与普通威胁区分 | ✅ 5px 粗+节点状锁定标记 vs 普通红三角 |
| 旧残阵是否可理解 | ✅ 虚线暗框 + 降权节点 + "旧残阵"标签 |
| 候选刀路后果是否清楚 | ✅ 刀路结果直接可视化（灰化/打叉/阻断/高亮） |
| 每张图 ≥2 条刀路 | ✅ 图1×2 / 图2×2 / 图3×2 |

### 是否建议进入 Gate1

**建议进入。**

理由：
- 五层视觉语法已建立稳定区分
- 候选刀路→后果的因果关系已可视化
- 去说明化版本可独立被理解
- 结构已经具备进入动态验证的语义基础
